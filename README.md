# 野境 WILDHAVEN

当前默认采用**单人私有访问**：页面、静态资源和 WebSocket 均要求 HTTP Basic 登录，用户名固定为 `admin`，密码为 `.env` 中的 `ADMIN_TOKEN`。浏览器首次访问会弹出登录框，公网必须经 HTTPS 使用。私有模式强制最多 1 个实时连接，第二个标签页/设备会被拒绝连接；关闭旧标签页后再打开新页面。单连接限制不等于识别自然人，口令只应由本人持有。

**挂机自动下线**：默认连续 30 分钟没有页面内鼠标、触摸、键盘或滚轮操作就断开实时连接、释放名额，清除页面管理口令及未应用草稿，并停止自动重连。点击“重新进入”或主动刷新页面可恢复观看，修改世界需重新解锁。切换后台、自动跟随、地图更新、推送和心跳不会刷新活动时间；服务器也会独立执行超时，即使页面挂起或没有运行前端计时器仍会断开。世界继续演化，不自动暂停。浏览器缓存的 HTTP Basic 凭据不会被此次下线清除，已显示的世界画面仍保留，这属于实时会话下线。持有口令的脚本能主动报告活动，本功能不识别人类，也不能阻止持有凭据者重新连接。

可在 `.env` 设置 `IDLE_TIMEOUT_SECONDS=1800`（单位：秒，允许 1–86400），修改后执行 `docker compose up -d` 生效。服务器每秒检查一次，正常关闭后释放名额；不响应关闭握手的连接会在约 2 秒后强制清理。后台休眠或断网后恢复页面时，前端也会检查实际经过时间，超时后不会自动恢复连接。

私有模式禁止空口令、少于 32 个字符和示例口令。应用使用有界的全局请求预算（突发 60 次，补充 10 次/秒）以及跨连接错误鉴权预算（突发 6 次，补充 1 次/10秒）。这不能替代代理层和云端抗 DDoS 防护。`/health` 无需登录但只返回 `{ok}`，详细指标在登录后的 `/health/details`，可用 `curl -u admin https://你的域名/health/details` 按提示输入密码。

面向低配置 Linux 服务器的共享数字生态模拟器。TypeScript + Node.js 24 + Canvas + WebSocket + SQLite；生产依赖只有 `ws`，无 GPU、外部 AI API、云服务或在线字体。前端仅渲染与发送控制命令，所有生物行为由服务器执行。

## 快速体验

安装 **Node.js 24.11 或更高的 24.x** 与 npm：

```bash
npm ci
cp .env.example .env
# 编辑 .env，将 ADMIN_TOKEN 替换为 openssl rand -hex 32 生成的口令。
npm run build
npm start
```

访问 `http://localhost:3000`，使用 `admin` 和管理口令登录。服务器启动即开始演化，关闭所有浏览器后仍继续。开发时 `npm run dev` 会先构建并监听服务端源码；修改前端后重新运行该命令构建。缺少有效口令时默认拒绝启动。原生运行可显式设置 `PRIVATE_MODE=false` 恢复共享观看，Compose 固定开启私有模式。

界面提供暂停、0.5–8 倍速度、13 项快捷参数、独立的47项详细参数与分析页、挑战方案、生态干预、保留进度扩图、小地图、资源图层和个体跟随。新世界默认 **512×384**，可逐次扩展至单边最多 **2048** 格。一天为 120 模拟秒，每季 6 天、每年 24 天，昼夜和季节实际影响生态；动物年龄以模拟秒计算。

### 观察与控制

- **独立观察视图**：可筛选植被/食草/食肉图层、全屏、拖拽与光标位置缩放；手机支持双指缩放。点击动物查看档案，或使用“随机观察一只”自动定位并跟随。手动拖动会退出跟随，空白处点击或 Esc 取消选择。
- **共享控制**：暂停、倍速与环境会影响所有访客。控制操作等待服务器确认，期间防止重复提交。13 项环境参数分为气候、生存、物种三个页签，五种挑战方案先形成草稿，点击“应用环境”才生效；可撤销，实时推送不会覆盖草稿。退出管理会清除本地草稿。
- **趋势图**：顶部卡片小曲线来自真实历史采样。主图默认 `log(1 + 数量)` 纵轴，可切线性刻度、筛选曲线，至少保留一个物种；悬停/轻触或聚焦后使用左右方向键读取具体数量。
- **连接反馈**：断线显示最后同步画面并自动重连，恢复同一运行世界时保留视角、选中个体、图层与环境草稿。重置/服务器重启导致世界运行标识变更时清除个体选择与草稿，避免旧状态作用于新世界。操作超时不会自动重放命令。
- **快捷键**：空格暂停/继续（需权限），`+ / -` 缩放，`0` 恢复全景，`F` 切换跟随，`Esc` 取消选择，`?` 查看操作说明。输入框和弹窗中不会触发世界快捷键。

### 独立参数与分析页

通过顶栏“参数与分析”或 `/settings.html` 进入生态实验室。47项参数分为气候强迫、水文与土壤、初级生产、分解与循环、摄食与生理、生命史与演化。每项显示单位、默认值、范围、机制与生效时机，支持跨分类搜索。观测站每项快捷参数的“精确编辑”可直达对应参数，快捷滑杆也改为连续取值。

详细页使用分组混合操作台：倍率和强度使用旋钮，温度使用直线刻度，阈值与无量纲比例使用推子，年龄/孕期/寿命使用时间码与时间带，速率、系数及距离使用相应横向刻度。数值读数仍可左右拖曳。每个参数有独立“精细”按钮，只将本通道的拖动、键盘和微调量缩小至0.1倍，不影响其他参数；没有全局精细开关，切换分组会保留各通道状态。Alt可进一步精调，Shift加速。

常用数值默认简短显示，小系数按数量级保留必要有效位，避免长串浮点尾数；时间码显示到百分之一秒。双击数值或点击铅笔会显示完整原值，Enter确认、Esc取消。显示舍入不会改写模型、JSON导出或存档中的精确值，键盘微调也基于原值计算。双击控件恢复默认，拖动中Esc撤回本次手势。未解锁或断线时控件不可操作，所有调节先形成草稿，点击应用后才影响共享世界。

展开“精确设置与单位换算”可使用温区上下限联动中心与宽度；寿命/成熟年龄/孕期可用秒或小数分钟输入；速率支持每秒与每分钟双向换算；分解常数可用参考半衰期设置；比例提供百分比输入，Q10提供每°C增幅换算。草食同化系数EU/VU使用每10VU的EU收益输入，不冒充无量纲百分比。

所有参数均可直接输入合法范围内的任意有限小数，不按滑杆步进或预设档位量化。每项有自定义绝对/相对微调量，±按钮与主数值框上下键使用该微调量，支持Shift×10、Alt÷10；提供单项恢复默认，以及部分过程的停用/恢复原值开关。数值精度受JavaScript浮点表示和模型自身时间/空间分辨率约束；输入更细不意味着过程具有无限分辨率。参考半衰期使用 `ln(2)/k`，条件为20°C且热适宜度、水分因子均为1，不是当前环境下的实际分解耗时。

编辑只形成草稿。核对“待应用变更”后统一应用到共享世界；传输包含当前值基线，若被其他访客抢先修改则拒绝本次应用。草稿保留，服务器推送不会覆盖未提交的编辑。页面口令仅保存在当前页内存，换页需要重新解锁；退出管理会清除草稿。

可导出当前/草稿参数JSON（不含口令），导入JSON先校验再生成草稿，不会立即修改世界。导入格式为 `schema: 1, model: "ABM-02", parameters: {...}`，最大64KB，拒绝未知字段、非有限数和越界值。载入挑战方案在实验室中包含全部47项基准；原观测页仍只调整13项快捷参数。

分析包括种群动态、资源限制、出生/死亡通量、捕食—猎物相轨迹、群体生理、当前种群结构与性状离散度，并可导出完整保留窗口的CSV。支持时间窗、人口曲线线性/对数、指针与键盘读数。响应预览的实线为草稿、虚线为当前参数，与服务器共用植物过程函数。

分析订阅使用 `/ws?mode=lab`，不发送精细地图、概览或动物坐标。历史通常每5模拟秒采样、最多240点；新指标从升级后记录，旧数据缺测留空。各单位、公式、统计口径和参考文献见 [生态模型与参数说明](docs/MODEL.md)。默认值是未按真实物种标定的演示参数，适合机制探索。

### 生态玩法

首页“原野气象与来客”展示当前天气、剩余模拟时间、下一次天气预报和自然火险。默认开启动态天气、自然山火与边界迁入；管理员可分别关闭，所有访客共享设置，重启后恢复。关闭动态天气仍保留昼夜与季节。预报按模拟时间推进，暂停冻结，倍速加快；网页离线不影响服务器进程。

- **天气过程**：连雨、干旱、热浪和冷锋叠加在基础参数与季节之上，实际影响入渗、蒸发、植物生长、分解和动物失水/代谢。基础参数不会被天气覆盖；雨天地图有轻量雨丝表现。新世界首次过程约在36模拟秒后，之后每144模拟秒进入一个新过程，各持续约60–90秒，季节影响类型分布。
- **自然山火**：每20模拟秒进行一次有界检查，干燥、高温与可燃植被共同增加机会；湿润环境不会自动起火。起火后留下实际火场、植被与能量损失，并可在“自然见闻”定位。火险0–100是相对指数，不是百分比发生概率。
- **边界迁入**：首次在90模拟秒、之后每120模拟秒尝试一次，季节决定机会。外部兔群4–8只或狐群2只，从有水分与植被的可通行边界进入，受全局容量限制；迁入不计入出生。迁入可能让灭绝物种重现，但不保证每次成功。此处是开放边界补充模型，尚未模拟世界外部种群或长距离迁徙路线。

天气由世界种子和模拟时刻确定，不访问在线天气服务；保存和恢复保持同一时刻的天气与预报。分区水土继续采用最多8点的气候积分近似；自动事件检查不扫描整张世界，迁入最多检查128个位置，地图雨丝最多48条，事件记录总数仍限制为12条。

| 分组 | 可调参数 | 实际影响 |
| --- | --- | --- |
| 气候 | 降雨 0–200%、温度 -10–45°C、日照 0–200%、肥力 0–200% | 植物恢复量由水、光、肥力和温度适宜度相乘；严寒/酷热增加动物消耗 |
| 生存 | 植物营养 30–200%、代谢 50–200%、寿命 50–200% | 摄食收益、饥饿速度、代际更替 |
| 物种 | 兔/狐繁殖率各 0–250%、兔/狐速度各 50–180%、感知 50–150%、变异 0–300% | 追逐与逃逸、觅食范围、后代基因差异；零繁殖率禁止自然出生，零变异精确继承 |

方案包括温和原野、丰水繁盛、旱季求生、凛冬试炼和捕食竞赛。载入方案会将全部 13 项参数改为该方案值，但保留当前地形、种群、时间、暂停与倍速状态。温度/日照也会在地图中形成寒冷、炎热或暗光的视觉反馈。

实验台可补种全图植被（每个草地格最多 +25 植被）、在当前观察区域附近投放最多 20 只兔子或 5 只狐狸，以及确认后引发局部山火。山火在当前区域附近随机选区，清除区域内 95% 植被，使动物损失 35 能量，可能造成死亡；地图保留并标记火场 30 模拟秒。干预不依赖模拟步进，暂停时也可执行，适合搭建实验条件。干预需要管理权限，全世界共享至少 1.5 秒的真实时间间隔，记录最近 12 次操作并保存到 SQLite。

新增的四条生态链：

- **水源与储水**：8×8 格土壤单元保存水分和水体余量，降雨补充、热量与光照促进蒸发。停雨后有缓冲期；动物缺水会寻水、在岸边饮水，持续脱水可死亡。
- **昼夜与季节**：夜间停止光合作用，兔群偏向夜间休息、狐狸偏向白昼休息；季节影响温度、降雨和繁殖概率。面板温度是基础值，顶部显示季节和时段修正后的实际值。
- **伴侣与幼体**：成熟异性邻居才可能受孕，孕期内能量不足会终止妊娠。兔/狐孕期分别 35/70 模拟秒，幼体跟随母体并短期哺育，成熟前移动较慢。初始和人工投放个体为成体。
- **分解与养分**：尸体与排泄物先形成碎屑，再受温湿度影响分解补充养分；植物生长同时消耗土壤水分和养分。模型用于观察机制，不表示现实物种的定量生理规律。

### 大世界如何保持轻量

“扩展疆域”将宽高各翻倍，面积增至 4 倍，旧地形、动物坐标、时间、参数与历史保留，在右侧和下侧增加新区。先写入新存档，成功后才切换共享世界；与重置共享 10 秒冷却。到达任一边长上限后停止扩展。扩图是一次性操作，最大规格建议先在目标服务器测量。

- 服务器采用紧凑数值数组，地形每格 1 字节、植被每格 4 字节，土壤按 8×8 聚合。内存仍随面积线性增加，并非无限地图。
- 植物以 32×32 分区更新，每步最多处理 64 个生物活跃区和 2 个轮巡区。远处区域用最多 8 点气候积分近似补算；所有动物仍逐步模拟，活跃区由动物决定，访客不会改变世界演化。
- 近景只推送视野内有变更的分块，视野超过 192 格时改为概览和种群聚合；概览最长边 128 像素，每 2 秒更新。点击远景或小地图可进入局部精细观察。
- 浏览器最多缓存 96 块小画布，避免创建整张大地图画布。土壤图层在精细分块中显示，远景保留自然概览。
- 存档压缩数值图层，植被按引擎自身的 0.01 单位编码。保存分区更新时间、土壤和随机状态，格式 v2 恢复后可重复继续演化；v1 升级时植被量化一次。

远处分区使用近似积分，植物总量和土壤均值反映各分区最近更新值，可能存在轮巡延迟。它不是逐格流体或全地图同步天气求解器；修改气候或扩图时会先结算旧区间。

种群灭绝后可先载入温和方案、应用、补种，再投放兔群和少量狐狸，无需重置世界。也可尝试：关闭兔群繁殖后提高狐狸速度；增大变异观察自然选择；在凛冬条件下控制种群规模，比较恢复策略。模型简化，以上是玩法实验，不是科学结论。

动物使用本地 Canvas 生成并缓存的 32px 像素精灵，支持行走/跳跃、追逐与摄食帧，按左右方向翻转。白兔长耳与白尾、狐狸尖耳与蓬尾保持不同轮廓；页面的物种图鉴和个体档案使用同一套形象。数字使用随项目打包的 Chakra Petch 字体，无运行时外部字体请求；授权见 `client/public/fonts/OFL.txt`，来源为 [Google Fonts 官方仓库](https://github.com/google/fonts/tree/main/ofl/chakrapetch)。

## 原生部署（当前选用）

推荐使用 [Git简化部署](deploy/GIT_DEPLOY.md)：首次 `git clone` 后运行安装脚本，以后只需 `sudo wildhaven update`；支持 `rollback` 和更换兼容仓库，配置与存档独立保留。

腾讯云OpenCloudOS 9 + 宝塔、2核2GB环境采用独立Node 24 + systemd托管，详细步骤见 [原生部署说明](deploy/NATIVE_DEPLOY.md)。配套 [systemd服务](deploy/wildhaven.service) 和 [原生配置示例](deploy/native.env.example) 使用独立目录、回环地址3001端口、512MB内存硬上限和约1核CPU配额，保留已有静态网站。无需Docker，不新增或修改宝塔反向代理；通过已有HTTPS入口或SSH隧道登录。只有systemd配置会对原生服务实施这些配额，Docker专用的 `MEM_LIMIT/CPU_LIMIT` 对原生运行无效。

## Linux Docker 部署（备选）

准备 Docker Engine 与 Compose v2 插件（[官方安装说明](https://docs.docker.com/engine/install/)）。建议从 1 核、512 MB 内存起步，留出镜像构建空间；小内存机器可在其他机器构建同架构镜像后导入。

```bash
cp .env.example .env
# 编辑 .env，将 ADMIN_TOKEN 替换为独立随机口令：openssl rand -hex 32
docker compose up -d --build
docker compose ps
docker compose logs -f --tail=100 eco
```

Compose 默认只绑定 `127.0.0.1`，按下一节配置域名和 HTTPS 后访问。浏览器先使用 `admin` 和管理口令登录，进入页面后点击“管理员解锁”再次输入同一口令即可控制。页面退出管理只清除页面内的控制口令，不会清除浏览器缓存的 HTTP Basic 凭据；结束使用可关闭专用隐私窗口，泄露后应修改口令并重启服务。

```bash
sudo systemctl enable --now docker
docker compose restart eco
docker compose stop              # 停止并保留数据
docker compose start             # 恢复运行
docker stats --no-stream
curl -f http://127.0.0.1:3000/health
```

`restart: unless-stopped` 支持异常退出后重启和主机开机后恢复；主动 stop 的容器需 start。健康检查报告状态，但 Docker 不会仅因 unhealthy 自动重启，请用外部监控检查 `/health`。应用在 SIGTERM/SIGINT 时存档退出。崩溃最多回退到最近一次定期存档；关机期间不进行离线追算。

## 域名、反向代理与 HTTPS

将域名 A/AAAA 指向服务器，放行 80/443。在服务器安装 [Caddy](https://caddyserver.com/docs/install)，使用 [deploy/Caddyfile](deploy/Caddyfile)，替换域名。Caddy 自动处理证书并转发 WebSocket。将 `.env` 改为：

```dotenv
BIND_IP=127.0.0.1
PUBLIC_ORIGIN=https://eco.example.com
```

```bash
docker compose up -d
sudo caddy validate --config /etc/caddy/Caddyfile
sudo systemctl reload caddy
```

把示例 Caddyfile 放入 `/etc/caddy/Caddyfile` 后再执行验证。已有 Nginx 时，在 HTTPS 站点的 location 中配置：

```nginx
location / {
    proxy_pass http://127.0.0.1:3000;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_read_timeout 90s;
    proxy_buffering off;
}
```

证书可通过所用发行版的 Certbot 集成部署。`PUBLIC_ORIGIN` 是完整浏览器源（协议、域名、非默认端口，无结尾 `/`），必须与实际访问一致；设置后其他来源的 WebSocket 会被拒绝。未设置时校验 Origin 与 Host。管理口令通过 WebSocket 消息发送，公网务必使用 HTTPS。生产仅暴露 80/443 与受限 SSH；数据卷、`.env` 和备份不应对外公开。不要配置 CORS 通配来源。

## 环境变量

`.env.example` 可直接复制。Compose 将宿主 PORT 映射至容器固定 3000；原生运行使用 PORT 本身。

| 变量 | 默认值 | 作用/范围 |
| --- | --- | --- |
| PORT / HOST | 3000 / 0.0.0.0 | 原生监听端口/地址 |
| BIND_IP | 127.0.0.1 | Compose 宿主绑定地址 |
| PRIVATE_MODE | true | 原生私有访问开关，Compose 固定为 true |
| IDLE_TIMEOUT_SECONDS | 1800 | 页面无操作自动下线时间，1–86400 秒；不受模拟暂停和倍速影响 |
| WORLD_WIDTH / WORLD_HEIGHT | 512 / 384 | 各 24–2048 格，仅新建/重置生效；旧世界可通过扩图保留进度 |
| WORLD_SEED | 42 | 0–4294967295，可重复随机种子 |
| MAX_ANIMALS | 1200 | 20–5000；降低后恢复时截断超额个体 |
| TICK_HZ | 5 | 1–20，服务器调度唤醒频率 |
| PUSH_HZ | 2 | 1–5，WebSocket 推送频率 |
| SAVE_SECONDS | 30 | 5–3600，存档周期 |
| MAX_CLIENTS | 1 | 私有模式强制为 1；原生共享模式允许 1–200 |
| DB_PATH | ./data/world.sqlite | 原生存档路径；容器固定 /app/data/world.sqlite |
| ADMIN_TOKEN | 空 | 私有模式要求至少32字符且非示例值，同时用于入口登录与页面控制 |
| PUBLIC_ORIGIN | 空 | 唯一允许的浏览器源，空时同 Host 校验 |
| MEM_LIMIT / CPU_LIMIT | 256m / 0.50 | Compose 内存/CPU 配额 |
| NODE_HEAP_MB | 128 | Compose V8 堆上限，需低于内存配额 |

最低资源可用 `64×48`、`MAX_ANIMALS=400`、`PUSH_HZ=1`、`MAX_CLIENTS=10` 起步。CPU 限制过低或倍速过高时，模拟会慢于墙钟时间；每步仍保持 0.2 模拟秒。每批最多追赶 40 步，并在每步结束后检查 12ms 耗时预算；超出时丢弃剩余完整步积压，保留不足一步的余量，让出线程处理连接与控制。单个生物步不能被中断，预算不是硬性延迟保证。倍速与网页访问人数无关。

### 高种群保护

- 创建世界和恢复存档均校验规模，个体总数最多 5000；自然繁殖与人工投放共用容量上限，满额时停止新增。
- 邻居搜索按物种分桶，每次搜索每桶最多检查 16 个候选，感知范围最大时每次最多检查 25×16 个候选；寻找威胁、猎物或伴侣分别执行。稀疏桶精确搜索，密集桶按个体与步数轮换采样，避免聚集时退化成全量两两比较；密集区域感知属于近似搜索，可能忽略实际最近个体。
- 超过 1200 个体时地图改用按物种批量绘制的色点，选中个体保留精灵；点击、筛选、缩放与跟随仍可使用。绘制耗时超过 12ms 时下一帧目标降至 15fps，隐藏页面停止绘制。
- 无观众时跳过网络帧生成；快照、命令回复和更新帧均检查发送积压。世界重置增加跨连接共享的 10 秒间隔，防止频繁创建世界和同步写库占满线程。存档拒绝额外顶层字段，避免覆盖实例方法或原型。

这些保护限制计算量与积压，实际流畅程度仍取决于设备、世界尺寸和访客数；请用下方满载基准在目标主机测量。

## 存档、备份与恢复

SQLite 单行保存完整世界，包括地形、植物、动物、随机数状态、控制参数、统计和最近 240 个采样点；使用 WAL 与 FULL 同步。每次存档以单条语句原子替换，不追加无限历史。`node:sqlite` 在 Node 24 中仍会显示实验性警告，项目只使用基础 DatabaseSync/backup API（[官方 Node 24 文档](https://nodejs.org/docs/latest-v24.x/api/sqlite.html)）。

在线备份使用 SQLite backup API，避免直接复制活动 WAL 数据库：

```bash
mkdir -p backups
docker compose exec eco node dist/server/backup.js /app/data/world.sqlite /app/data/backup.sqlite
docker compose cp eco:/app/data/backup.sqlite backups/world.sqlite
```

备份包含最近已提交存档，最多落后 SAVE_SECONDS。将本地备份改名加日期，并复制到其他磁盘或机器；容器内备份只是中转，同一数据卷不能防磁盘损坏。原生运行：

```bash
node dist/server/backup.js data/world.sqlite backups/world.sqlite
```

恢复（先保存当前文件供排查；以下操作将用备份替换当前世界）：

```bash
docker compose stop eco
docker compose cp eco:/app/data/world.sqlite backups/before-restore.sqlite
docker compose cp backups/world.sqlite eco:/app/data/world.sqlite
# 已停止所有写入进程后清除旧 WAL/SHM，并恢复文件所有权。
docker compose run --rm --no-deps --user root --entrypoint node eco -e "const f=require('node:fs');for(const p of ['/app/data/world.sqlite-wal','/app/data/world.sqlite-shm']){try{f.unlinkSync(p)}catch(e){if(e.code!=='ENOENT')throw e}}f.chownSync('/app/data/world.sqlite',1000,1000)"
docker compose start eco
docker compose logs --tail=50 eco
```

如果是崩溃/损坏现场，应在替换前把整个 `/app/data` 目录复制出来保留 WAL/SHM，而不是只复制主库。原生恢复同样需先停服务、备份整个 data 目录、替换主库并清除对应旧 WAL/SHM。**不要运行 `docker compose down -v`**，它会删除持久化卷。

## 更新与回滚

1. 按上述方法创建备份，并保留当前版本源码/镜像。
2. 拉取新版本或替换项目文件，保留 `.env`。
3. 执行 `docker compose up -d --build`，检查日志、`/health` 和页面连接。
4. 若需回滚，换回旧版源码重新构建；存档格式不兼容时同时恢复升级前备份。

当前存档格式为 **v2**，可读取旧 v1，首次保存后写入新格式；升级前请备份，旧程序无法读取 v2。旧档补齐水分、性别与土壤等属性，保留种群和进度，不会强制使用新的默认世界大小。不兼容格式或损坏存档会阻止启动，应用不会自动覆盖坏档。修改种子需管理员重置；扩大地图优先使用“扩展疆域”。重置前请备份，重置使用环境变量和确定种子产生初始世界。

## 排障

| 现象 | 检查与处理 |
| --- | --- |
| 页面有内容但地图一直连接 | 检查 PUBLIC_ORIGIN、代理 Upgrade/Host、HTTPS 的 wss、MAX_CLIENTS |
| 控制项灰色 | 等待连接；若配置口令，点击管理员解锁 |
| 参数似乎不生效 | 降雨/肥力作用于植物恢复，土壤储水和种群有滞后；0 降雨不会立即耗尽水分 |
| 某个物种消失 | 属于模拟允许的结果；可先改善环境，再通过实验台重新投放，不会自动补种 |
| unhealthy / save failed | 检查磁盘空间和卷权限；恢复可写后下一次存档会恢复健康 |
| 启动立即退出 | 检查环境变量范围、数据库格式、SQLite 权限与日志；保留坏档再恢复备份 |
| 容器反复 OOM | `docker inspect` 检查 OOMKilled，降低规模/动物上限/访客数或提高 MEM_LIMIT |
| CPU/带宽较高 | 降低倍速、PUSH_HZ、MAX_ANIMALS 和 MAX_CLIENTS；检查 `docker stats` |

Compose 日志轮转最多约 15 MB。世界与历史数据有界，但数据卷没有硬磁盘配额；需要主机监控磁盘余量，并自行轮转备份。`/health/details` 在私有模式登录后返回 tick、个体数/容量、客户端数、最近批次模拟耗时、最近批次丢弃的积压步数 droppedSteps、RSS，不包含口令；私有模式的 `/health` 只返回健康状态。

## 架构与生态规则

```text
server/world.ts       确定性生态引擎，与 HTTP/浏览器无关
server/habitat.ts     紧凑图层、分区更新、水分/养分/分解与压缩编码
server/viewport.ts    只读视野订阅、变化分块与远景聚合
server/clock.ts       固定 200ms 生物步长、倍速和有界补帧
server/store.ts       SQLite 存档/恢复
server/index.ts       静态文件、共享世界、WebSocket 与生命周期
server/config.ts      环境变量验证和资源边界
shared/types.ts       领域模型
shared/climate.ts     昼夜/季节日历与气候修正
shared/environment.ts 13项快捷参数、47项合并定义与挑战方案
shared/model.ts       34项过程系数、共用响应函数、生命史派生值
shared/analysis.ts    通量计算与CSV统计口径
shared/species.ts     物种特征表与派生饥饿值
shared/protocol.ts    网络量化/紧凑元组协议
client/main.ts        连接、命令确认、环境草稿、个体档案
client/map.ts         地图缓存、增量绘制、插值、双指/拖拽/跟随
client/chart.ts       历史曲线、真实迷你趋势、悬停与键盘读数
client/interactions.ts 可测试的相机、草稿与命令状态
client/environment-panel.ts 参数分组与可访问的页签
client/settings.ts    独立参数页、管理、草稿与数据导入导出
client/laboratory-charts.ts 可访问Canvas图表与条件响应预览
client/sprites.ts      缓存像素精灵帧、物种肖像
tests/                规则、时钟、持久化、服务器集成测试
```

服务器只创建一个 World。固定步长驱动所有生物，植物按分区至少间隔一模拟秒更新；食草动物扫描邻近植被，发现捕食者后优先逃逸；捕食者通过 8×8 格空间桶查询邻近猎物，追逐时消耗体力。双方都受能量、水分、年龄和可通行地形约束。摄食按效率转化能量，繁殖消耗双亲能量，后代继承双亲均值与轻微变异的速度/代谢基因。水体与岩地不可穿越。没有全地图最短路径算法，动物会局部绕障和随机探索，可能被孤立地形困住，这也是简化模型的边界。

自然选择可改变基因分布，但这不是科学预测模型。饥饿值由能量与物种容量推导，防止摄食后两个状态不一致。当前仍未模拟疾病、寄生虫、复杂遗传、多种植物竞争、授粉、真实水流和地形侵蚀。新增物种可扩展 Species、speciesTraits、个体属性与 world 的行为分支；新增机制优先写为引擎模块，在 step 中按固定阶段调用，并扩展保存版本与测试。

网络按访客视野发送变化分块和动物紧凑量化帧，从不发送全图精细地形；共用统计/概览，分别编码各视野。`watch` 订阅无需管理权限，每连接每10秒最多40次；修改命令最多20次，含畸形消息的总上限60次。另有连接上限、心跳、4KB消息上限、来源校验和管理口令。慢客户端缓冲超过256KB时断开重连获取快照，避免遗漏分块。实验室仅订阅统计，隐藏页面暂停图表绘制；服务器不受影响。

```bash
npm run check

```

测试覆盖可重复随机演化、精确恢复、暂停/倍速、死亡/摄食/繁殖、人口上限、密集聚集计算量、调度耗时预算、异常规模/存档拒绝、越界防护、无人访问持续运行、多客户端共享控制、鉴权、跨源拒绝、重置限流与真实 SQLite 重启恢复。基准运行 18,000 步（1 小时模拟时间）输出 P95、RSS、存档和网络帧大小。`bench:stress` 在 1200/5000 满载下测试分散、单点聚集、纯食草觅食三类场景，以最大感知范围运行，每场预热 20 步、测量 120 步，保持数量避免灭绝掩盖开销，并验证存档可恢复。这里的快进基准不是连续运行一小时的稳定性测试，也不能替代目标 Linux 机器和浏览器测量。

本项目开发环境为 Windows + Node 24.11，已执行构建、类型检查、规则与服务器测试，以及 Edge 浏览器检查。当前开发环境没有 Docker，未在此处执行容器构建或目标 Linux 服务器部署。`.github/workflows/ci.yml` 提供 Linux 自动测试和 Docker 构建检查；上线前请在实际主机验证 `docker compose config`、`up --build`、备份恢复与资源占用。

大世界基准另运行 3,000 步并执行实际 SQLite 保存/恢复，输出初始化、P95、分区更新上限、视野数据量和分阶段内存。一次 Windows + Node 24.11、编译后 JS、128MB V8 堆的 **2048×1536** 测量：P95 约 **0.81ms**，首次局部帧（含概览）约 **83KB**，未变化帧约 **5.6KB**，保存约 **77ms**，保存后 RSS 约 **97MB**（同时保留恢复副本后约 114MB）。这是约百只动物的基准，不能代表 5,000 个体或多访客满载。满载测试中 5,000 个体分散场景 P95 约 45ms，低配主机建议保留默认 1,200 上限或更低。`tsx` 会增加工具开销，具体数值以目标主机测量为准。
